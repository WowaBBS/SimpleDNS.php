# 0001. DnsRecord содержит DnsRdata, а не наследует его

**Контекст.** Рассматривали модель «ресурсная запись = один объект», где `DnsRdata`
наследует `DnsRecord` (как `RR_Header` в Go-библиотеках). Это убрало бы обёртку
`->rdata->…` и дублирование типа.

**Решение.** Оставили композицию: `DnsRecord` (имя, тип, класс, TTL, `DnsRdata`)
и отдельная иерархия `DnsRdata`. Тип записи выводится из класса данных (ADR 0004).

**Причины.**
- В иерархии столкнулись бы сигнатуры: `DnsRecord::toJson(): array` против
  `DnsRdata::toText(): string` (фатал при объявлении), `fromJson(array)` против
  `fromText(string)`, `serialize()` с разным смыслом (вся запись против RDATA).
- Поле `?DnsRdata $rdata` при наследовании стало бы рекурсивным; его пришлось бы
  убрать, и `DnsRecord` превратился бы в абстрактную рамку.
- Разбор работает фабрикой: прочитать заголовок, выбрать класс по типу и отдать ему
  RDATA. При наследовании пришлось бы создавать объект до чтения данных.

**Следствия.** Тип стал вычисляемым свойством, появился `RdataRegistry::typeFor()`.

**Не делать.** Не переводить RDATA на наследование от записи без пересмотра ADR:
это каскад переименований `serialize`/`toText`/`fromText` во всех типах.
