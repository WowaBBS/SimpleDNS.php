# 0003. Секции сообщения — объекты-списки, а не массивы

**Контекст.** Секции были массивами, и каждый потребитель повторял одно и то же:
перебор для записи, перебор для JSON, поиск OPT в `additional`.

**Решение.** `DnsList` реализует `ArrayAccess`, `Countable`, `IteratorAggregate`,
`JsonSerializable`. Наследники: `DnsQuestionList`, `DnsRecordList`.

**Что это дало.**
- Существующий синтаксис сохранён: `$m->answers[] = …`, `count($m->answers)`,
  `foreach`, `$m->answers[0]` работают без правок.
- В список уехали запись секции (`writeTo`), JSON-секция (`writeJsonTo`),
  чтение по счётчику (`fromReader`) и разбор (`fromJsonReader`).
- Появились доменные выборки: `byType`, `byName`, `find`, `opt`, `names`, `ttls`.
- Тип элемента проверяется на любом входе; список остаётся плотным.

**Следствия.** `jsonSerialize()` отдаёт `toJson()` элементов, поэтому
`json_encode($m->answers)` даёт массив, а не `{}`.

**Не делать.** Не заменять списки массивами; не использовать `array_*` напрямую
(для этого есть `toArray()`); не допускать дырок в индексах.
